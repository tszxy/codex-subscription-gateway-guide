# 07 · 验收清单、固定 Coding 任务与测试边界

## 1. 离线自动测试

在独立 Python venv 中执行：

```bash
python -m venv .venv
# Linux/macOS
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m unittest discover -s tests -v
# Windows 改为 .venv\Scripts\python.exe
```

测试使用 HTTPX MockTransport 和 ASGITransport，不访问 OpenAI，不读取生产凭证，不消耗订阅额度。覆盖：

- 明确额度错误转为中文终止提示，保存原始 code/status。
- 无账号/冷却提示不误报明确额度。
- 401、502 和未知错误原样转发。
- 成功 SSE 正文与内容类型保持，认证头/查询参数传到模拟上游。
- 上游连接/等待超时转为独立的 502/504 网关错误。
- 畸形 JSON 不导致错误分类崩溃。
- 模型查询只提取允许字段，不返回私有正文。
- 同秒/同模型合并，不同秒/不同模型保留，去重存储有界。
- 不在 SSH 命令白名单里的输入被拒绝。

这些测试验证本仓库辅助层，不验证 CPA 内部真实账号调度。

## 2. 全链路验收

| 项目 | 验收方法 | 通过条件 |
| --- | --- | --- |
| 内部监听 | `ss -lntp` | 8317/8318 仅回环监听 |
| CPA 文本连接 | 内部一次 smoke test | 真实模型成功回应 |
| 错误代理连接 | 8318 一次 smoke test | 同样能回应 |
| HTTPS | 公网域名请求 | 证书正常，客户端无需忽略验证 |
| key 验证 | 错 key 发送请求 | 被拒绝，不静默回退 |
| 管理边界 | 公网 `/v0/management`、`/v8/management` | 404，无面板公开 |
| 桌面 Code | 固定任务 | 文本、工具调用、测试完成 |
| 模型映射 | 对照任务时间和路由日志 | 主任务走期望模型 |
| 强度 | 核对最终转换字段 | 随 UI 选择变化 |
| 查询权限 | SSH `recent` / `id` | 前者元数据，后者拒绝 |
| 去重 | 观察重复路由记录 | 同秒相同模型只显示一行 |
| 终止错误 | 离线模拟已知代码 | 中文详情、正确分类 |

`/v1/models` 能列出模型只证明目录响应；真实完成一轮请求才验证这次请求的访问权限。文本 smoke test 不包含工具调用，不足以证明整个 Code 工作流兼容。

## 3. 固定 Coding 任务

比较不同供应商时，使用同一个初始目录、同一提示、同一模型和强度。建议下面的 Python 任务，无外部网络和依赖，容易复查：

```text
在空目录实现一个 Python 3.10+ 命令行工具 ledger.py。
输入 CSV，列名固定为 date,category,amount。
date 严格使用 YYYY-MM-DD；amount 用 Decimal，保留两位小数。
支持：
1. python ledger.py INPUT.csv：按 category 输出总额，类别按字典序。
2. --month YYYY-MM：仅统计指定月份。
3. --json：输出 JSON，金额用字符串，避免浮点误差。
4. 空文件/缺列/无效日期/无效金额有明确错误，错误写 stderr，退出码 2。
5. 成功退出码 0；负金额可用于退款。
只使用 Python 标准库。
编写 unittest，至少覆盖正常汇总、退款、月份过滤、JSON、金额精度和四类错误。
自己运行测试，修复失败，最后简要说明实现与测试结果。
不要访问网络，不要安装依赖，不要额外实现数据库或图形界面。
```

固定样例：

```csv
date,category,amount
2026-01-01,food,10.10
2026-01-02,food,-0.10
2026-01-05,travel,20.00
2026-02-01,food,3.33
```

全部汇总应为 food `13.33`、travel `20.00`；January 过滤应为 food `10.00`、travel `20.00`。测试不能只重复实现逻辑，要独立断言这些已知结果和错误退出码。

## 4. 公平比较的记录方式

每个平台至少做一次新会话冷启动，再做一次明确标记的缓存条件测试。不要在一个平台带十万 token 历史、另一个平台空会话，然后只比较总费用。

记录开始/结束时间、完整任务结果、请求数量、输入/缓存/输出用量、推理强度、失败重试、账号是否切换，以及服务的实际扣费或配额变化。价格比较优先看完整任务成本与正确率，不能只看一个“百万 token 混合均价”。

跑同一任务不证明模型身份，但能提供任务正确率、工具兼容性、速度与用量的可重复观察。

## 5. 本手册已经确认与尚未确认的范围

| 项目 | 证据类型/状态 |
| --- | --- |
| CPA 轮换与 retry 参数语义 | v8.0.24 示例配置及源码核对 |
| 实例的正常 Codex 请求 | 实际部署有请求反馈和模型日志 |
| 桌面角色映射 | 实例配置与路由记录核对 |
| 桌面强度控件切换 | 曾观察 High → Extra；最终所有等级出站值未逐个断言 |
| 全池错误的代理呈现 | 离线模拟验证 |
| 所有真实账号同时额度耗尽 | 未人为制造端到端实验 |
| 新服务器完整从零安装 | 公开模板需要读者按本章现场验收 |
| 官方精确剩余额度/重置倒计时 | 本仓库查询工具不实现 |
| 物理模型内部身份 | 本仓库不能独立鉴定 |

仓库测试通过表示辅助代码在测试条件下行为正确，不表示所有版本的 CC Switch、Claude Desktop、CPA 或所有账号都保证长期兼容。
